> Read this first in every new session. Update the **Progress log** at the end of each session.

## 1. Existing state (inspected 2026-11-21)
The project directory was **empty**. This is a greenfield build. Nothing existed to preserve.
Environment: Windows 11, Python 3.13, Node 26 / npm 11. **Not installed locally:** Redis, PostgreSQL, Docker (Docker is prohibited by requirement).
Local dev therefore uses SQLite (fallback) and in-memory cache/Celery; production requires Neon PostgreSQL and Redis (enforced in `config/settings/prod.py`).

## 2. Target architecture
- `backend/` Django 6.1 + DRF, modular apps under `backend/apps/`, JWT (short-lived access, rotating/blacklisted refresh).
- `frontend/` (not started) React + TypeScript + Vite; one app with separate route trees: platform site, platform admin, restaurant site, restaurant admin, manager, cashier, staff, customer.
- Tenancy: **shared database, shared schema, row-level tenant FK**. Tenant resolved only from the validated Host (`<slug>.PLATFORM_DOMAIN` or a *verified* `RestaurantDomain`); never from headers/body. Custom domains need no restructuring.
- Identity: global `User` (email unique) + per-tenant `Membership(role, branches)`. Roles are resolved server-side on every request; tokens carry no role. A token from tenant A grants nothing on tenant B.
- Roles/levels: platform_admin 1, restaurant_admin 2, manager 3, cashier 4, kitchen/waiter/delivery 5, customer 6. Role assignment requires the actor's level to be strictly higher than the target's (`can_assign_role`).
- Data layer enforcement: `TenantOwnedModel` (mandatory `restaurant` FK, auto-scoped default manager using a context variable, `unscoped` escape hatch) and `BranchOwnedModel` (branch must belong to the same restaurant, validated on save). `BranchScopedQuerysetMixin` restricts viewsets to the caller's tenant + branches.
- Cross-cutting: append-only `AuditLog`, `IdempotencyKey` + `run_idempotent()` (scoped by tenant/user/operation, payload-hash checked, committed atomically with the business effect), uniform error envelope, `/healthz` + `/readyz`.
- Money: `DecimalField` only. Backend computes all totals. Snapshots for order items, salary structures and receipts. Financial records are never deleted (void/refund/adjust).
- Integrations (structure + env vars + docs; cannot be live-tested without credentials): Brevo, Monime, Google OAuth, Cloudflare R2.
- No Docker. Processes: `gunicorn`/`waitress` (WSGI), `daphne`/`uvicorn` (ASGI for Channels, Phase 5/9), `celery worker`, `celery beat`.

## 3. Security decisions
- The onboarding "initials@year" password convention is **not** implemented as a credential. Plan: random one-time password-setup link (or random temp password) with short expiry, `must_change_password`, never logged. The model/flow for forced change + expiry already exists and is tested.
- Login: uniform failure response (no account enumeration), per-email lockout after 5 failures (15 min, cache-backed so Redis makes it distributed), scoped throttling, host-bound membership check, audit entries (emails only, never passwords).
- The 5-click hidden login is a UX interaction only, not a security control.

## 6. Running locally (no Docker)
```powershell
cd backend
python -m venv .venv; .venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env   # then edit (dev settings load defaults if unset)
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py createsuperuser   # then set is_platform_admin=True in the shell
.venv\Scripts\python manage.py runserver
.venv\Scripts\python -m pytest
```
Frontend: `cd frontend; npm install; npm run dev` (http://localhost:5173), `npm test`, `npm run build`. Create a platform admin with `create_platform_admin` (env vars above). `.claude/launch.json` defines `api` and `web` dev servers.
Tenant hosts in dev: `http://<slug>.localhost:8000` (browsers resolve `*.localhost` to loopback). Use Neon `DATABASE_URL` and a Redis `REDIS_URL` to match production.
